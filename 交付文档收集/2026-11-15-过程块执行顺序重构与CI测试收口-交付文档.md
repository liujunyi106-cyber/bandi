# 2026-11-15 过程块执行顺序重构与 CI 环境敏感测试收口 —— 交付文档

## 1. 当日完成的核心模块/功能

### 1.1 过程块按真实执行顺序平铺展示（核心）

**问题**：过程块（思考/工具/Skill/注记）此前被 `buildBuckets()` 按**工具类别重新分组**，
真实执行序列 `read a.py → edit a.py → bash pytest → read b.py` 渲染成
「读取文件 ×2 / 读取修改文件 ×1 / 其他工具 ×1」——**跨类时序永久丢失**，用户无法看出
「先改了 a.py 才跑的测试」。且三级折叠（总行→分类行→明细行）需要点两次才能看到读了哪个文件。

**参考源结论**（详见 `交付文档收集/2026-11-15-DSH对话信息流与过程块分析.md`，849 行）：

- DSH **没有「过程块」容器组件**：`ChatView.tsx:146-151` 拿到的是**已排序的 key 数组**，
  逐 key 分发到 keyed slot，**每个节点就是一行**；唯一折叠原语是 24px 的 `DisclosureRow`。
- 顺序权威是 `anchorSeq`（`chat-snapshot-builder.ts:135-139` `orderedVisible`），
  且工具节点的 anchor 取**`tool/call` 事件的 seq，不是 result 的 seq**（`tool.ts:265-267`）
  ——所以工具行定位在「开始执行」处，与结果到达次序无关。
- bandi 的根因三层叠加：`ProcessNode` 类型**没有顺序字段** → `buildBuckets` 按类别重组
  → 三级折叠。讽刺的是 `id` 里其实编码了 `:tool:${nodes.length + 1}`，
  但**渲染前被丢弃**。

**实现**：

- `ProcessThoughtNode` / `ProcessToolNode` / `ProcessSkillNode` / `ProcessNoteNode`
  四个变体各加可选 `seq?: number`（`chat-store.ts:18-112`）。
- 新增 `buildRows(nodes): TimelineRow[]`（`ProcessBlock.tsx`）：按**数组下标即执行顺序**
  平铺，`seq` 可选覆盖；skill 节点按技能拆成多行并生成唯一 key。
- 新增 `TimelineItem` 组件：一行渲染一个节点，行前缀是该类别图标（替代原分类行），
  明细直接可见；保留知识条目「展示/收起」、思考「摘要+展开正文」、子代理嵌套树、
  失败/skip 状态图标、`onShowDetail` 点击。
- 删除已废弃的 `buildBuckets`（L69-115）、`BucketRow`（L392-521）、`interface Bucket`（L63-66）
  与不再使用的 `toolLabel` 导入。

**行为变化**：分类行（`process-bucket-*` testid）整体移除；明细默认可见（点一次过程总行即可），
不再需要二次点开分类。

### 1.2 进度条加粗

`KernelGate.tsx` 进度条 `h-1`（4px）→ `h-2`（8px），与胶囊边框观感匹配。

原 CI 用 `--deselect` 硬排除 14 个「只在开发机稳定」的用例。本次逐项定位根因，

### 1.4 OCR 缺权重时的可行动错误

`image_ocr.py` 原只在 `PADDLEOCR_AVAILABLE`（包可导入）为真时放行，但 PaddleOCR
**首次推理才下载模型**，缺权重时底层抛 `json.exception.parse_error.101: ... empty input`
——对用户完全不可读。新增 `_model_weights_ready()` 探测 `~/.paddleocr`、`~/.paddlex`
下的 `whl`/`official_models`/`ocr_models` 目录，并在 `_describe_ocr_error()` 中把
权重缺失类异常翻译为可行动提示。

## 3. 与架构设计对齐情况

- **前端设计规划 §8（过程消息）**：原设计是「字段行 + 多级折叠」。本次将「分类行」这一级
  移除，改为**一行一节点**，仍保持「无卡片、字段行」的外观基调，只是信息从默认隐藏变为默认可见。
  这是对 §8 的**主动调整**，理由是分类归并会销毁执行时序，而时序是用户理解 Agent 行为的主要线索。
- **DSH 参考**（外部参考纪律 §3）：本次引用了 `deepseek-harness` 的
  `chat-snapshot-builder.ts` / `tool.ts` / `invariant.ts` / `DisclosureRow.tsx`，
  借鉴「anchorSeq 排序 + 每节点一行 + 24px 单行折叠」三处设计；
  **未借鉴**其 `ToolCallView` 服务端渲染意图（Terminal/Diff/Read 卡片）——那需要后端改工具基类
  与帧协议（`tool_call_start` 当前连 `tool_name` 都不带，`states.py:2003-2013`），属跨端架构改动，
  建议单独立批。
- **契约纪律 §6b**：契约从「钉分桶 testid」改为「钉渲染行顺序与内容」——按 §6b
  「契约钉行为不钉实现」，分类是实现细节、顺序是产品承诺。
- **保留 bandi 优于 DSH 的能力**：记忆写入按 `long_term`/`working`/`compaction` 分档、
  终态注记折叠后仍可见、失败行 `onShowDetail` 详情入口，均未丢失。
